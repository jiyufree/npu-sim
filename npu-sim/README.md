# Mini NPU Simulator

## 1. 실행 방법
- **환경**: Python 3.8 이상 (NumPy 등 외부 라이브러리 사용 배제, 순수 내장 기능만 사용)
- **실행**: 터미널에서 `python main.py`를 입력하여 프로그램을 시작합니다.
- **모드 선택**:
  - `1` 입력: 3x3 필터 A, B와 패턴을 사용자가 콘솔에 직접 입력하여 MAC 연산 및 판정 결과를 확인합니다. (잘못된 입력 시 재입력 유도)
  - `2` 입력: 같은 폴더에 위치한 `data.json` 파일을 읽어와 크기별(5x5, 13x13, 25x25) 패턴을 일괄 채점(PASS/FAIL)하고, 크기별 연산 시간 성능 표를 출력합니다.

## 2. 구현 요약
- **데이터 구조 및 MAC 연산**: 2차원 리스트 형태의 숫자 배열을 사용하여 패턴과 필터를 정의하고, 외부 라이브러리 없이 순수 이중 for문을 사용하여 같은 위치의 인덱스를 곱하고 누적하는 MAC(Multiply-Accumulate) 연산을 직접 구현했습니다.
- **라벨 정규화(표준화)**: `data.json` 내부에 혼재된 정답 라벨(`+`, `cross`, `x`, `ex` 등)을 프로그램 내부 판정 기준인 `Cross`와 `X`로 통일(정규화)하여 텍스트 매칭 오류를 차단했습니다.
- **점수 비교 정책**: 컴퓨터의 부동소수점 연산 누적 오차를 방지하기 위해, 두 점수의 단순 비교(`==`) 대신 허용오차(`abs(A - B) < 1e-9`) 기반의 Epsilon 정책을 적용하여 미세한 차이는 동점(UNDECIDED)으로 안전하게 처리했습니다.

## 3. 결과 리포트 (실패 원인 및 시간 복잡도 분석)

### 실패 원인 분석 (왜 0 FAIL이 되었는가?)
현재 분석한 미니 `data.json` 테스트 케이스에서는 총 2개의 케이스가 모두 PASS 처리되어 FAIL이 0건으로 발생했습니다. 실패 케이스가 발생하지 않은 이유는 프로그램 내부적으로 발생할 수 있는 문제를 선제적으로 방어했기 때문입니다.
1. **스키마/데이터 및 로직 문제 차단**: 대소문자나 표기법이 제멋대로인 라벨 데이터를 그대로 비교했다면 '로직 문제'로 인해 억울한 FAIL이 발생했겠지만, 사전에 `normalize_label` 함수를 거쳐 표준 라벨로 변환했기 때문에 문자열 불일치 오류를 막았습니다.
2. **수치 비교 문제 차단**: MAC 연산을 수백 번 반복하면 0.9000000000000000와 0.8999999999999999처럼 미세한 부동소수점 오차가 발생합니다. 이를 간과하고 같다/크다를 판정했다면 수치 비교 문제로 FAIL이 났겠지만, 허용오차(epsilon) 비교 정책을 도입하여 올바르게 동점 처리(UNDECIDED) 할 수 있었습니다.

### 시간 복잡도 분석 (O(N²)의 근거)
모드 2 실행 시 출력되는 성능 분석(시간 측정) 표를 확인한 결과, 패턴의 크기(N)가 커짐에 따라 연산 시간이 기하급수적으로 증가하는 것을 확인했습니다.
- 3x3 크기에서는 총 연산 횟수가 9번(N²)에 불과하여 평균 시간이 매우 짧게 측정(약 0.002ms)되었습니다.
- 반면 25x25 크기에서는 연산 횟수가 625번으로 급증하며, 연산 시간 역시 약 0.070ms 수준으로 가파르게 상승했습니다.
- 이는 구현한 MAC 연산이 이중 반복문(`for i in range(n): for j in range(n):`)을 통해 입력 배열의 모든 칸을 정확히 한 번씩 순회하기 때문이며, 측정된 지표가 O(N²)의 시간 복잡도를 명확하게 증명하고 있습니다.

## 4. 학습 목표 및 원리 이해 (평가 대비)

본 과제를 통해 아래 6가지의 핵심 원리를 설명할 수 있게 되었습니다.

1. **MAC 연산과 AI에서의 중요성**: MAC 연산은 입력 데이터와 필터의 같은 위치 값을 곱하고 결과를 누적하는 과정입니다. 이미지 패턴 하나를 찾기 위해 수억 번의 덧셈/곱셈이 필요하므로, 이 단순 반복 작업을 병렬로 빠르게 쏟아낼 수 있는 NPU(AI 전용 칩)가 필수적입니다.
2. **유사도(점수) 계산 원리**: 퍼즐(입력) 위에 필터(정답지)를 겹친 뒤, 위치별로 숫자를 곱하고 더합니다. 두 모양이 유사할수록 '1'이 같은 자리에 겹치며 최종 합산 점수가 높게 산출됩니다.
3. **라벨 정규화의 이유**: 협업이나 외부 데이터 수집 시 작성자의 기준(`+`, `cross` 등)이 통일되지 않아 파편화됩니다. 이를 내부의 단일 규칙으로 정규화해야만 정확한 조건문 판정과 PASS/FAIL 처리가 가능해집니다.
4. **부동소수점 오차와 허용오차 정책**: 컴퓨터는 실수를 2진수로 저장하여 무한소수를 잘라내므로 미세한 오차가 발생합니다. MAC 연산이 반복될수록 이 오차가 커져 수학적으로 같은 값도 다르게 인식하므로, epsilon 기반의 오차 허용 정책이 필수적입니다.
5. **크기 증가에 따른 시간 복잡도 O(N²)**: 측정 결과 패턴의 가로/세로 길이(N)가 커질수록 시간은 N의 제곱 비율로 증가했습니다. 배열의 모든 요소를 순회해야 하는 2D 행렬 연산의 태생적 한계이자 특징입니다.
6. **실패 케이스 진단법**: 
   - **데이터/스키마 문제**: 배열 크기가 다르거나 필수 키가 없는 경우
   - **로직 문제**: 정규화를 누락하거나 비교 조건문을 잘못 작성한 경우
   - **수치 비교 문제**: epsilon 처리를 누락하여 부동소수점 오차 때문에 결과가 틀린 경우
